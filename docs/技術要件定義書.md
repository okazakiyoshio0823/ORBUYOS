## 4. データベース設計

### 4.1 テーブル構成

```sql
-- 作業者
CREATE TABLE workers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  role TEXT DEFAULT 'worker',
  industry TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 車両
CREATE TABLE vehicles (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  plate_number TEXT,
  maker TEXT,
  model TEXT,
  model_code TEXT,
  year INTEGER,
  color TEXT,
  industry TEXT NOT NULL,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 作業予定
CREATE TABLE work_schedules (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  work_date DATE NOT NULL,
  worker_id INTEGER NOT NULL,
  vehicle_id INTEGER,
  part_id INTEGER,
  service_id INTEGER,
  planned_start TIME,
  planned_minutes INTEGER,
  actual_start TIME,
  actual_minutes INTEGER,
  status TEXT DEFAULT 'pending',
  industry TEXT NOT NULL,
  FOREIGN KEY (worker_id) REFERENCES workers(id),
  FOREIGN KEY (vehicle_id) REFERENCES vehicles(id)
);

-- 部品マスタ
CREATE TABLE parts_master (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  category TEXT,
  default_minutes INTEGER DEFAULT 30
);

-- 整備メニューマスタ
CREATE TABLE service_menus (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  category TEXT,
  default_minutes INTEGER DEFAULT 60,
  color TEXT DEFAULT '#4CAF50'
);

-- 作業者別実績
CREATE TABLE worker_performance (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  worker_id INTEGER NOT NULL,
  model_code TEXT,
  part_id INTEGER,
  avg_minutes INTEGER,
  total_count INTEGER DEFAULT 0,
  total_minutes INTEGER DEFAULT 0
);
```

### 4.2 インデックス設計

```sql
CREATE INDEX idx_schedules_date ON work_schedules(work_date);
CREATE INDEX idx_schedules_worker ON work_schedules(worker_id);
CREATE INDEX idx_schedules_industry ON work_schedules(industry);
CREATE INDEX idx_vehicles_industry ON vehicles(industry);
CREATE INDEX idx_workers_industry ON workers(industry);
CREATE INDEX idx_performance_worker ON worker_performance(worker_id);
```

## 5. 非機能要件

### 5.1 パフォーマンス

| 指標 | 目標 | 測定方法 |
|-----|------|---------|
| ページ読み込み | 3秒以内 | Lighthouse |
| API応答時間 | 500ms以内 | ブラウザDevTools |
| DBクエリ | 100ms以内 | SQLite EXPLAIN |
| 同時接続 | 50ユーザー | 負荷テスト |

### 5.2 可用性

| 項目 | 要件 |
|-----|------|
| 稼働時間 | 8:00〜19:00で99%以上 |
| MTTR（平均復旧時間） | 30分以内 |
| バックアップ | 日次（手動） |
| リストア | 1時間以内 |

### 5.3 セキュリティ

| 項目 | 対策 |
|-----|------|
| 認証 | セッション管理（将来実装） |
| SQLインジェクション | プレースホルダ使用 |
| XSS | React自動エスケープ |
| CSRF | Same-Origin Policy |
| ファイルアクセス制御 | OS権限で保護 |

### 5.4 スケーラビリティ

| 項目 | 現状 | 拡張案 |
|-----|------|--------|
| データベース | SQLite | PostgreSQL移行 |
| 同時接続数 | 50 | 500（DB分離） |
| ストレージ | ローカルディスク | クラウドストレージ |
| デプロイ | 単一サーバー | 負荷分散 |

## 9. バックアップ・リストア

### 9.1 バックアップ対象

| 対象 | パス | 頻度 |
|-----|------|------|
| SQLiteデータベース | `data.db` | 日次 |
| 設定ファイル | `.env` | 変更時 |

### 9.2 バックアップ手順

```bash
# データベースのコピー
cp data.db data_backup_$(date +%Y%m%d).db

# 定期バックアップ（Windowsタスクスケジューラ / Cron）
# 毎日AM2:00に実行
```

### 9.3 リストア手順

```bash
# サーバー停止
pm2 stop orbiyos

# データベースを復元
cp data_backup_20260215.db data.db

# サーバー再起動
pm2 start orbiyos
```

## 10. トラブルシューティング

### 10.1 よくある問題

| 問題 | 原因 | 対処法 |
|-----|------|--------|
| ポート3000が使用中 | 他プロセスが使用 | `PORT=3001 npm run dev` |
| データベースロック | 複数プロセス起動 | プロセスを1つに |
| 音声入力が動かない | HTTPS未使用 | localhost使用 |
| CSVインポート失敗 | フォーマット不正 | カラム名確認 |

### 10.2 デバッグ方法

```bash
# データベース内容確認
sqlite3 data.db "SELECT * FROM workers;"

# ログ確認
npm run dev | tee output.log

# ポート使用状況
netstat -ano | findstr :3000  # Windows
lsof -i :3000                  # macOS/Linux
```
